# R3nzSkin 16.21.1-fork.4 诊断与状态修复版使用说明

## 当前状态

本包以 hydy100 的 `16.21.1` 为核心基线，针对游戏 `16.21` 补丁构建。
`ChinaServer` 和 `RiotGamesServers` 是工程配置名，**不是当前服务器可用性认证**。
包内启动器来自仓库中的历史公开源码，不包含上游维护者未开源的新版加载器。
当前未完成游戏内运行验证，不能保证当前国服能加载、换肤或避免账号处罚。

本版修复了公开启动器中界面与后台各有一份状态变量的问题：原来点击 Start 可能没有传到后台，后台状态也无法回到界面，导致持续显示 Not Injected。
已用跨文件回归测试验证状态共享；这项修复不等于已经验证当前国服的实际加载能力。

fork.4 在诊断基础上区分模块已存在、不存在和查询不可用：查询不可用时显示 `Query unavailable`，暂停加载尝试；只有模块查询明确找到 DLL 才显示 `Injected`。
加载线程结束和原始退出值均不直接构成加载成功的证据。原有加载方式和权限请求保持不变。
停止状态只枚举进程名，不打开游戏句柄；取消启动时自动启用调试权限。一次查询不可用后，该会话不再重复查询，需停止至少两秒再 Start 或重启启动器才会重新检查。
`Stop` 仅阻止后续尝试，不能撤销已经执行的 DLL 加载。
本机只读复核发现，管理员游戏句柄缺少请求的读取权限；此修复不会恢复该权限，也不代表国服换肤已修复。
窗口底部的 Load 是加载流程，Probe 是模块查询；两者分开显示。
日志 `InjectorDiagnostics.log` 写在启动器所在目录，使用 `[DEBUG-r3diag]` 标记。
日志包含时间、目标进程编号、阶段和数值错误码，不包含账号、游戏内数据或内存内容。

## 环境与包的选择

- Windows 10/11 x64。
- .NET Framework 4.8（Windows 11 通常已自带）。
- 与 VS 2022 构建兼容的 [Microsoft Visual C++ x64 运行库](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)。
- 国服研究选 `ChinaServer-x64.zip`，Riot 客户端研究选 `RiotGamesServers-x64.zip`，不要混用两个包中的 DLL。

## 下载与校验

1. 从本 Fork 的 Release 或成功的 Windows Actions 中取得 ZIP 和同名 `.sha256` 文件。
2. 用 PowerShell 执行 `Get-FileHash -LiteralPath '.\下载的文件.zip' -Algorithm SHA256`，与 `.sha256` 中的值比较。
3. 将整个 ZIP 解压到一个独立目录；不要直接从压缩包中运行。目录可包含中文和空格，无需放入游戏安装目录。
4. 解压后应包含 `R3nzSkin.dll`、`R3nzSkin_Injector.exe`、`Launch.cmd`、本说明、`manifest.json`、`CHECKSUMS.sha256` 和 `LICENSE`。
5. `manifest.json` 记录发布版本、游戏补丁、构建配置、源码提交及文件哈希。更新时使用新目录，保留原包便于回退。

有 Python 与源码时，也可在解压之前执行完整包校验：

```powershell
python tools/package_release.py verify '下载的文件.zip'
```

## 测试环境中的操作方式

本节描述公开启动器原有流程，不代表该流程已在当前国服验证成功。
涉及真实账号的运行验证应先确认适当的测试账号和环境。

1. 完全解压后运行 `Launch.cmd`，打开启动器。直接打开 EXE 时也会使用其自身目录定位 DLL。
2. 在指定的测试环境中进入对局，观察启动器的 Client、Game 状态。
3. 游戏进入后点击 `Start`。若无法加载或游戏退出，停止此次测试，记录版本和具体错误；反复尝试不能替代版本适配。
4. 如果 DLL 已实际初始化，在游戏内按 `Insert` 打开菜单，选择皮肤。
5. UI 显示 `Injected` 仅证明模块查询找到 DLL；还应以游戏内菜单和实际外观变化验证初始化和换肤结果。
6. 退出游戏后关闭启动器。未提供在正在进行的正式对局中自动测试的功能。

本轮诊断只需一次测试：出现 Failed 或等待状态长时间不变时点 Stop，保留底部诊断文字和同目录日志。
若记录了原始线程退出值，它仅用于诊断，不能当作完整的 x64 模块地址或游戏初始化成功的证明。
错误码只能确定哪个调用返回了什么结果，单凭 Access denied 不能确定是哪个系统组件作出的决定。

源码目录中可用以下命令收集结构化报告（替换为自己的测试包目录）：

```powershell
.\scripts\collect-diagnostics.ps1 -PackageDirectory '测试包完整目录' -Interactive
```

此脚本只提示人工步骤并读取现有日志，不启动启动器，也不执行加载。
报告保存在测试目录的 `diagnostic-report.json`，按 PID 分组，保留首次加载结果、首次记录的失败与最后结果，最新 PID 不继承旧进程的成功状态。首次记录的失败也不等于根因。
退出码 1 表示已捕获加载阶段失败或模块查询不可用，2 表示未确认模块存在或尚无足够日志；退出码 0 仅表示观察到模块，不等于换肤成功。

此 Fork 不自动下载和替换程序，也不随机重命名 EXE。后续版本仍从本 Fork 获取完整包。

## 常见问题与记录

| 现象 | 检查与处理 |
| --- | --- |
| 提示缺少 DLL/EXE | 确认完整解压，并保持同一包的两个二进制在同一目录 |
| 提示缺少运行库 | 检查 .NET Framework 4.8 与 VC++ x64 运行库 |
| Client/Game 为 Not Found | 确认目标客户端或测试对局已实际启动；当前源码只识别原有进程名 |
| Query unavailable | 当前无法确认模块；启动器暂停加载尝试，保留 Probe 错误。管理员运行也可能无法获得所需读取权限 |
| 无法加载、进入后没有菜单或游戏退出 | 当前公开加载方式或核心可能不兼容；保留包版本、游戏完整版本和日志，不能据 UI 状态判定已成功 |
| 提示找不到特征 | 记录首个失败项和游戏完整版本；换皮肤数据库不能修复该问题 |
| 游戏升级后原包失效 | 重新做版本核查，等待对应补丁；不要将旧产物覆盖到新版本目录 |

提交问题时提供：包名、`manifest.json` 的源码提交、游戏完整版本、Windows 版本、复现步骤和错误信息。
先清理日志中的个人路径、账号标识与令牌。不要提交游戏二进制或进程转储。

维护者的构建、打包和草稿发布步骤见仓库 `docs/RELEASING.md`。
